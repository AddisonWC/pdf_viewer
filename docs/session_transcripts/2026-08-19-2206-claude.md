Here's the suite properly described.

## Shape

One file, no framework. `check(label, cond)` records a pass/fail line; `main()` runs a hand-written list of 43 functions in order. Because failures append to a list instead of raising, every check in a group runs even after one fails — so a broken run reports all 222 outcomes, not just the first. The flip side: **a test not added to `main()`'s list never runs and nothing says so.**

Everything shares one `QApplication` on Qt's `offscreen` platform, and `XDG_STATE_HOME` is redirected to a temp dir so the real last-read-page file isn't read or polluted.

## Fixtures

Seven PDFs built by eight `_make_*` functions at import (line 294 onward), each existing to provoke one behaviour: a 40-page 3-level TOC with running headers *and* body text repeating each title (to force header-highlight disambiguation); a plain 20-page doc; an AES-256 encrypted one; a citation doc whose link targets a *middle* entry in tightly-packed numbered references; a scanned doc with no text layer plus deliberate edge dirt; a figure doc; a mark-dense figure doc; and an image-figure doc where only the caption is extractable text.

They're written to fixed names under `$TMPDIR` — worth knowing that two concurrent runs would clobber each other's fixtures.

## What the 43 groups cover

**Navigation and history (8)** — `H/L/J/K/Home/End` paging against a 2-column grid, status-overlay format, grid resize, and the history model: back/forward, negative-index clamping, no duplicate entry when re-jumping to the current page, and the subtle one — refining a search must *update* the existing history entry rather than deepen it, so one Back still reaches the pre-search page instead of the first match.

**Zoom and crop (4)** — cursor-anchored zoom matching `ZOOM_STEP`, zooming out from a content crop staying inside the page, box-zoom collapse to 1×1 and restore of the saved grid, and that a recrop after collapse renders *exactly once* (no full-page flash).

**Content detection (8)** — the largest cluster. A scan with no text layer still yields a crop whose edges sit on the body and ignore edge dirt; figure pages crop from the image rather than the caption; graphic-mark bucketing/clipping/union; a 200k-mark performance bound; the scan budget stopping the figure pass partway; failed detection still dropping the crop; and a superseded detection clearing its loading dot without undoing a manual zoom.

**Search (3)** — incremental matching without Enter, focus handoff, red field on no match, and a late result arriving after Escape being discarded rather than navigating.

**TOC (3)** — `Y/U/I/O` fluid level nav (dive, climb, close-in-place, recommit), header highlight landing on the destination page and clearing on close, and a no-TOC document being a safe no-op.

**Render internals (5)** — dark-mode pixel math including hue preservation, pixmap cache key shape/DPR/byte-budget/LRU eviction, and two staleness guards: a stale-*size* result and a stale-*generation* result must each fail to clobber the current pixmap or the in-flight count. Plus the busy indicator's frame ordering and 2 Hz tick.

**Document lifetime (4)** — the strongest material here. A file deleted out from under an open document: pages still render, search still works, `Ctrl+N` still opens, and rewriting the path doesn't mutate the open doc. A move *during* load, verified through `/proc/self/fd`. Encrypted docs staying unlocked across worker threads, stream-opens and copies, with a wrong-password retry. And that a failed last-page save leaves the previous file byte-identical with no temp file behind.

**Windows and integrations (8)** — copy windows inheriting crop and outliving their parent; Wayland requested only in a Wayland session; citation links producing a Scholar query that doesn't bleed into the adjacent reference entries; the Ask-Claude launcher's full argv; PRIMARY vs clipboard selection semantics; and entry-point/helper-prompt paths.

## What it doesn't cover

Not pixels — it can't judge appearance. Not real-world PDF weirdness — every fixture is PyMuPDF-generated and well-formed. Not I/O, as established. Not real concurrency beyond the specific staleness guards. And `GOTCHAS.md:16` notes a structural blind spot: `QTest.keyClick` synthesizes keys with no text, so some shortcut regressions are invisible to it by construction.

The honest summary: it's strongest exactly where this program is unusual — content detection, staleness, and surviving a file that moves or vanishes — and empty where a conventional suite would be strong.
