## What changed

**Wayland gate** (`pdfviewer.py:24`) — `QT_QPA_PLATFORM` is now `setdefault`-ed to `wayland` only when `WAYLAND_DISPLAY` or `XDG_SESSION_TYPE=wayland` is present. **Search cancel** (`_exit_search`) — bumps `_search_generation` and clears `_search_inflight`, so a result that lands after Escape is discarded by the existing staleness guard instead of repopulating matches and navigating.

**Ctrl+N crop** — `open_copy` passes the new `autocrop=False` and copies `crop_rect`/`crop_source_rect`, so the duplicate opens at the parent's crop rather than re-running the random-sample detection. A copy of an uncropped window stays uncropped. I deliberately left `_open_linked_copy` (center-click) detecting its own: it lands on a *different* page, so a box-zoom crop carried over from the source window would usually frame the wrong region there. Easy to change if you'd rather it inherit too.

**Copy windows outliving their parent** — worth correcting one thing: the copy isn't a subprocess. It's a window in the same process. The actual cause is that **Qt closes a window's transient children along with it**, and `_set_transient_parent` is what produced both the placement you like and the death-link.

The fix keeps the placement and drops the tie: set the transient parent before `show()` as before, then release it one event-loop turn later, once the compositor has already placed the window. I reproduced the original behavior against your real compositor (child hidden on parent close) and confirmed the fix there too — the copy stays visible at an identical position after the parent closes, for both Ctrl+N and center-click.

The one thing given up is the compositor keeping a copy stacked above its parent. That seemed clearly worth trading for the copy staying open, but say the word if you'd rather have it back.
