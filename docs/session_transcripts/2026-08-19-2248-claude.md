## Assistant (final reply) — 2026-08-19 22:49:59 PDT

Yes, mildly — but the honest answer is that most of what you'd gain is cheaper than a rewrite, and I'd only do the conversion if you keep it very thin.

**What's actually wrong with the current suite** (I read `tests/test_pdfviewer.py` and ran it — 20.5s, 222 checks, all green):

1. **No way to run one test.** `main()` has a hardcoded list; debugging `test_dense_figure_page_detects_promptly` means running all 43 groups or editing the file. This is the real pain.
2. **`check()` never aborts.** A failed precondition doesn't stop the test — it cascades into a pile of downstream failures that all look like separate bugs. `tests/test_pdfviewer.py:396` even has two `check(..., True)` lines papering over a branch to keep counts stable.
3. **No teardown on failure.** `v.close()` sits at the end of each test body (`tests/test_pdfviewer.py:336` etc.). Any exception leaks a live window into the shared `QApplication` and the global `QThreadPool`, so the *next* test is running in a polluted process.

**What pytest actually buys you:** `-k` selection, per-test isolation on exception, fixture teardown in a `finally`, tracebacks with locals, and parametrization — the seven `_make_*_pdf` documents and the detection tests are the obvious candidates. What it does *not* buy: parallelism worth having (20s), and `pytest-qt` is useless to you since `pump()` is better than `qtbot.wait*` for this codebase's thread-pool + timer model.

**The cheap alternative:** ~20 lines on the existing runner — `sys.argv` substring filter over the test list, and wrap each call in `try/finally` with a helper that closes any leftover top-level windows. That gets you #1 and #3 with no dependency and no churn across 1617 lines. #2 stays broken.

**My recommendation:** convert, but as a mechanical pass, not a redesign. `check(label, cond)` → `assert cond, label`; the module-level PDF construction (`tests/test_pdfviewer.py:298-312`) → one session-scoped fixture directory; `new_viewer` → a fixture that yields and closes. Keep `pump()` byte-for-byte — it's the load-bearing part and it's correct. Keep it one file. Don't add `pytest-qt` or `xdist`.

The one thing you lose is the per-check "ok" transcript that makes the 222-count meaningful in `docs/DEVLOG.md`; `pytest -v` reports 43 tests, not 222 assertions. If that number is how you track coverage of the suite over time, note the discontinuity in the devlog when you do it.
