## Assistant (final reply) — 2026-08-11 18:29:57 PDT

Diagnosed and fixed. The regression came from the figure-detection work added on 2026-08-10.

## Root cause

`_graphic_rects` built one `fitz.Rect` per painted mark in a Python loop. That's fine for a normal page (~100 marks), but a filled-contour/mesh plot emits every cell as a separate mark — **48,932 and 64,929 marks on two pages of `vilar--subcell.pdf`**. At ~17µs per mark that's **1.4 seconds for a single page**, and because it's pure Python it holds the GIL the whole time, so the whole app froze even though detection runs on the thread pool. A 10-page sampled crop usually draws one or two of those pages, so `C` cost 1.8–3.1s.

## Fixes (pdfviewer.py)

1. **`_graphic_rects` is vectorized** — normalize/clip/cover-drop/bucket in numpy array ops, per-cell union via `argsort` + `np.minimum.reduceat`. Output verified **byte-identical to the old loop across 676 real pages**.
2. **A `0.5s` figure-pass budget in `_ContentDetectTask`.** `get_bboxlog()` itself is the remaining floor (~4.5µs/mark, 285ms on the worst page, GIL-held about half of it) and is unbounded in page complexity — a document where *every* sampled page is a dense plot would still cost seconds. Once a task spends its budget it finishes the remaining pages text-only. Checked before each page, so the first page always gets the figure pass and single-page `Shift+C` is never degraded; degradation is gentle because the result is a union.

Measured on the file you named: worst page **1411ms → 342ms**, sampled crop **1.8–3.1s → 0.12–0.81s**, worst-case sample **3.5s → 0.58s**.

## One separate bug found in that code

`_GRAPHIC_BBOX_KINDS` listed `"image"` — a string MuPDF never emits (it's `fill-image`/`fill-imgmask`). So the image half of that fix has been dead since it was written, and pages whose figure is a photo or bitmap plot still cropped down to the caption. I fixed the spelling; across your literature dir it changes 43 of 586 pages, **every one growing to include a figure that was previously cut off** — e.g. `ern,guermond--IDP_time_stepping.pdf` p14 has two images at y 96–200 and the old crop started at y=203, cutting both. Text kinds stay excluded on purpose, since text arrives via `get_text("blocks")` where the watermark filter runs.
