## Bug 2 — current-match color didn't move on same-page matches

Stepping to the next match with `n` routes through `_navigate` → `_show_current_pages`, which re-renders each cell and hands the result to `QLabel.setPixmap`. When the next match is on a page already visible, `first_page` doesn't change, so the "re-render" is a cache hit that returns the *identical* pixmap. The fix mirrors what the code already does elsewhere: `clear_all_selections` and `clear_search_highlight` both call `cell.update()` explicitly precisely because overlay-only changes can't rely on a pixmap swap. Automating them puts the account itself at risk of being flagged. I won't build on that, and I'd advise against it.

Your read is basically correct. The API-vs-subscription split is, among other things, a metering boundary: subscriptions are flat-rate for *interactive human use through Anthropic's own clients*; the API is metered pay-per-token for *programmatic* use. A custom app driving a subscription is precisely the thing that boundary exists to prevent — so there's no clever legitimate path that gives you integrated in-app convenience *on the subscription*.

What you *can* legitimately bolt on around the browser route is thin and doesn't cross into automation: a hotkey that opens claude.ai and reveals/copies the current PDF's file path so it's a fast drag, maybe a pre-written prompt copied to the clipboard. 1. Pull text **lines** (not blocks) from `get_text("dict")`.

3. Read line-by-line **down to the next marker**, so it captures the whole entry (including continuation lines) and stops cleanly at the next one — no bleed in either direction.
4. **Column-aware**: it clusters the marker x-positions into columns (a >40pt gap starts a new one) and confines the read to the anchor's column, so a two-column references page doesn't splice in the neighbouring column.
